# 配置以 config.yaml 为唯一真相，表单只是它的视图

**Status**: accepted

`config.yaml` 是唯一权威来源，基础设置表单只是它的一层视图：保存时用 `yaml.v3` 的 Node API 只改写表单管辖的那些键，其余字节（注释、程序不认识的自定义键、键顺序）原样保留，保存前留一份 `config.yaml.bak`。因为用户升级时正是靠注释理解变更，全量重新序列化会把这份资产抹掉；而另写一份 overrides 文件会让同一个生效值有两个来源，用户改了 YAML 却被表单覆盖，排查成本远高于收益。

## Considered Options

- **全量重新序列化**：实现最简单，但丢掉 `config.example.yaml` 里的全部中文注释与未知键，也破坏"老配置必须还能读"的承诺。
- **`ui-overrides.yaml` 叠加**：完全不碰用户文件，但造出两个真相；同一个值可能来自两个文件，冲突时无提示。
- **只 patch 表单键**（选中）：需要额外写"保留注释与未知键"的测试，这是本决策唯一的新增成本。

## Consequences

- 写入路径必须经过测试保护：改目标键生效、注释保留、未知键保留、键顺序保留。
- 表单字段与 `config.yaml` 键名的对应关系以 `docs/prototype/admin-v2.html` 为基础页字段清单，界面文案用 `GLOSSARY.md` 的词汇，键名不出现在界面上。
- 保存后必须区分"已生效"与"需重启"：热重载只覆盖检测间隔与 cron，端口、sub-store、面板密钥等要重启才生效。
